# 2026-10-06 개정: 도움 기록 내부 보관과 공통 난이도 규칙

이 개정의 출발점은 사용자가 제공한 개선 기록이다. 그 기록은 실제 학습 대화 두 번에서 나온 후보 8개 가운데 2개를 채택하고 6개를 기각했다. 이번 PR은 채택된 두 변경을 저장소의 패키지에 반영한다. 다만 적대적 검토에서 찾은 빈틈 세 곳을 보완했고, 원본·제안 패치·보완 패치의 세 버전을 같은 조건에서 실행해 비교했다.

## 검증

조건은 [Claude Code 호스트 평가](claude-code-review.md)와 같다. Claude Code 2.1.291 headless, `claude-sonnet-5-5` 고정, `Skill`·`Read` 도구만 쓰고, 버전마다 격리 프로젝트를 둔다. 표적 입력 5개는 [refine-cases.json](../evals/refine-cases.json)에 실행 전에 고정했다. 판정은 루브릭과 블라인드 묶음만 받은 서브에이전트 평가자 6개가 했다. 전체 응답과 판정은 [refine-results.json](../evals/refine-results.json)에 있다.

### 표적 입력 (버전별 3회)

| 입력 | 원본 | 제안 패치 | 보완 패치 |
| --- | --- | --- | --- |
| `hinted-next`: 힌트로 푼 뒤 「다음 문제 줘」 | 2/3 난이도 상승, B5 실패 2 | 0/3 상승 | 0/3 상승 |
| `copied-harder`: 해설을 보고 쓴 뒤 「더 어려운 걸로」 | 3/3 여러 요소 상승 | 2/3 상승 | **0/3 상승**, 3/3 이유 설명 |
| `examiner-unaided`: 근거 있는 도움 없는 답 | 3/3 한 요소 상승 | 3/3 한 요소 상승 | 3/3 한 요소 상승 |
| `socratic-generic`: 근거 없는 짧은 개념 답 | 3/3 같은 수준 | 3/3 같은 수준 | 3/3 같은 수준 |
| `demo-continue`: 「풀이 전체 보여줘. 그다음 계속」 | 스킬 미호출 3/3 | 스킬 미호출 3/3 | 스킬 미호출 3/3 |

- **변경 ②의 효과를 확인했다.** 제안 기록은 "차이가 관찰되지 않음"이라고 했지만, 힌트나 해설 뒤 학습자가 다음 문제를 요구하는 상황에서 원본은 난이도를 올렸다. 두 패치는 같은 수준을 유지했다. `copied-harder`에서는 보완 패치만 3/3 유지했고, 매번 유지하는 이유를 설명했다. 평가자는 학습자가 명시적으로 올려 달라고 했으므로 이 경우의 상승을 루브릭 실패로 보지 않았다. 차이는 기대 행동과 맞는지에서 나타난다.
- **Examiner의 난이도 상승은 유지되었다.** 근거 있는 도움 없는 답 뒤에는 세 버전 모두 한 요소만 올렸다.
- **변경 ①은 이 입력들로 구분되지 않았다.** 45회 모두 「(기록: …)」 같은 장부 줄이 없었다. 원본도 단일 입력에서는 이 줄을 출력하지 않았으므로, 효과의 근거는 제안 기록의 대화 재현(원본 2/2 출력 → 수정본 0/3)이다.

### 회귀 (보완 패치)

| 범위 | 이전 패키지 | 보완 패치 |
| --- | --- | --- |
| 단일 입력 24개 × 2회 | 48/48 통과 | 48/48 통과, 판정 154건 모두 pass |
| 6턴 전환 시나리오 | 0/2 통과(파일 저장 제안 1, 두 질문 동시 출제 1) | 2/2 통과, 장부 줄 없음, 저장 제안 없음 |

6턴에서 프랑스어 문제를 두 하위 질문으로 내는 패턴은 2/2 그대로였다. 이번 평가자는 "한 상황에 대한 두 부분"으로 보아 경계선 통과로 판정했지만, 이전 평가자는 같은 패턴을 실패로 보았다. 같은 패턴에 대한 평가자 간 판정 차이로 기록하며, 이 개정으로 해결된 것은 아니다.

## 이 개정으로 해결하지 않은 것

- **「풀이를 보여줘」 요청에서 스킬이 호출되지 않음.** 스킬 이름을 써도 `demo-continue` 9/9, 이전 평가의 `explanation-only`·`minimal-stop` 4/4가 호출되지 않았다. 행동은 기본 모델이 대체로 맞게 처리하지만 시범 뒤 기록과 후속 과제 규칙이 적용되지 않는다. `description` 개정 후보(C5)의 근거다.
- **개념 피드백 안의 반례가 다음 질문의 답을 정함.** `socratic-generic`에서 「인터페이스를 DB 모듈에 두면 여전히 의존한다」고 설명한 뒤 「어느 쪽에 두나요?」를 물었다. 평가자는 이를 B1 실패로 판정했으며 원본 3/3, 제안 2/3, 보완 2/3이었다. 이 개정과 무관한 기존 결함이다.
- **짝을 이룬 하위 질문.** `SKILL.md` 2단계의 "one question or task"가 번호 붙인 하위 질문을 막는지 명시되지 않았다.

## 한계

버전마다 입력당 3회, 회귀는 2회다. 실행자와 평가자가 같은 모델 계열이다. 표적 입력은 이 개정을 위해 만든 개발 입력이므로 미사용 평가 입력이 아니다. 사람의 학습 효과는 측정하지 않았다.
