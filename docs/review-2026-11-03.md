# 2026-11-03 work-to-skill v0.1.2 반영과 적대적 리뷰

`work-to-skill` v0.1.2(2026-11-01)의 두 가지 내용 변경을 teach-skill에 반영하고, 그 반영을 두 차례 적대적 리뷰했다. 설치 패키지(`skills/teach-skill/`)는 바꾸지 않았다.

## v0.1.2 변경과 반영

| v0.1.2 변경 | teach-skill 판단 | 반영 |
| --- | --- | --- |
| 생성 스킬 이름은 호스트의 frontmatter 제한을 지킨다. 예: Anthropic은 이름에 `anthropic`·`claude`를 금지 | `teach-skill`에는 예약어가 없다. `name` 11자, `description` 489자, XML 태그 없음 | 패키지 변경 없음 |
| 개선은 같은 원천 지식을 받은 무스킬 기준선이나 이전 버전에 대해서만 주장한다. 지식 없는 기준선이 이미 통과하는 사례는 개선을 보일 수 없다 | [Claude Code 호스트 평가](claude-code-review.md)의 기준선은 스킬도 원 자료도 받지 않았고, 단일 입력 24개 중 20개를 두 번 모두 통과했다 | [rubric-v1.1](../evals/rubric.md)의 비교 규칙과 실행 계약, 평가 기록의 종합, 두 README의 주장 범위를 좁힘 |

## 리뷰 조건

| | Codex Astra | Claude Opus 5.5 | GPT-6.1-sol |
| --- | --- | --- | --- |
| 실행 | `codex exec -m gpt-6-astra --ephemeral -s read-only` | omp 서브에이전트 `adversarial-opus55`(xhigh), 읽기 전용 | omp 서브에이전트 `adversarial-sol61`(xhigh), 읽기 전용 |
| 1차 입력 | 같은 프롬프트([prompt.txt](../evals/review-2026-11-03/prompt.txt), [manifest](../evals/review-2026-11-03/prompt-manifest.md)) | 같은 프롬프트 + 저장소·로컬 파일 읽기, 웹 조회(Anthropic·Codex 문서) | 같은 프롬프트 + 저장소·로컬 파일 읽기(로컬 `work-to-skill`·`code-review` 지침) |
| 2차 입력 | 실행 안 함 | 1차 처리 뒤 작업 트리와 1차 원문. 공통 지시문은 이 기록 아래 절에 요약 | 같음 |
| 모델 근거 | CLI 출력의 `model: gpt-6-astra`. 출력 로그는 보관하지 않음 | 에이전트 정의의 모델 고정. 응답 메타데이터는 보관하지 않음 | 같음 |

1차 프롬프트는 v0.1.2 반영의 완결성(Q1)과 패키지와 yardstick의 텍스트 충돌(Q2)을 물었다. 발견이 없어도 되는 결과로 두었고, 발견마다 인용·증거 유형·변경 이득과 손실·그대로 둘 때와의 비교를 요구했다. 이미 기록된 열린 항목 네 가지는 다시 제기하지 말라고 했다. 2차는 1차 처리가 지적을 바르게 해소했는지, 새 모순이나 증거 오기가 없는지(이 기록 포함), 저장소 문서 사이에 남은 불일치가 없는지를 같은 형식으로 물었다.

처음 계획한 Claude Fable 5.1 리뷰는 `claude -p --bare`가 로그인을 읽지 못해 실패했고, 재실행 도중 사용자 요청으로 Opus 5.5·GPT-6.1-sol로 바꾸었다. 원문은 [evals/review-2026-11-03](../evals/review-2026-11-03)에 있다(1차: `astra.json`, `opus-5-5.json`, `gpt-6-1-sol.json`; 2차: `round2-*.json`).

1차 원문이 인용한 일부 문구(rubric의 "(the supplied learning principles)", README의 "pasting the same principles", 평가 기록의 "원칙과 스킬을 함께 준 효과")는 처리 과정에서 바뀌어 현재 파일에 없다. 리뷰받은 상태는 `prompt.txt`에 들어 있다. manifest의 `evals/rubric.md`와 `git diff` 해시도 그 상태의 값이다. 2차 처리 뒤의 변경은 어느 리뷰의 대상도 아니다.

## 한계

- 텍스트 리뷰다. 스킬을 실행하지 않았고, 같은 원 자료를 준 기준선도 실행하지 않았다. 원 슬라이드가 저장소에 없어 그 기준선은 자료 제공 여부에 달려 있다.
- 세 리뷰어의 입력 범위가 같지 않다. Astra는 1차만 실행했고 프롬프트만 검토했다고 보고했다.
- Claude Code 평가 대상은 2026-10-06 개정 전 패키지다. 이 차이는 이번 변경 전부터 README에 드러나 있지 않았고, 이번에는 다루지 않았다.
- 모델 판정은 전문가 인증이 아니다.
