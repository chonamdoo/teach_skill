# Claude Code 호스트 평가 기록

기록 시점: 2026-10-06. 평가 기준은 [rubric-v1](../evals/rubric.md)이며, 기준과 입력은 수정하지 않았다. 대상 패키지 해시는 [영어 버전 평가](english-review.md)와 동일하다. 이전 기록에서 미검증으로 남았던 세 가지를 새로 확인했다.

- Claude Code 호스트에서의 실제 대화 실행
- 같은 입력의 반복 실행(각 2회)
- 스킬 없는 기준선과의 짝 비교

학습 효과(C 계층)는 측정하지 않았다. 합성 학습자 입력이며 사람의 이해·전이·장기 기억은 확인하지 않았다.

## 실행 조건

| 항목 | 값 |
| --- | --- |
| 호스트 | Claude Code 2.1.291 headless(`claude -p`), 단일 입력마다 새 문맥. 다중 턴은 `--resume`으로 실제 이전 응답 유지 |
| 모델 | `claude-sonnet-5-5` 고정. 호스트가 보조 호출에 `claude-haiku-4-5`를 함께 사용 |
| 도구 | `Skill`, `Read`만. 웹·쓰기·실행·타이머·알림·저장 없음 |
| 설치 | 격리 프로젝트에 `npx --yes skills@1.7.0 add <local checkout> --skill teach-skill --agent claude-code --copy --yes`. 설치된 3개 파일 해시가 원본과 일치 |
| 기준선 | 같은 플래그, 스킬이 없는 빈 프로젝트 |
| 입력 | `english-cases.json` 23개 + `repair-cases.json` 1개(개발·회귀용) + `english-transitions.json` 6턴 |
| 실행 수 | 단일 입력 24 × 2조건 × 2회 = 96. 다중 턴은 스킬 2회, 기준선 1회 |
| 판정 | 서로 분리된 Claude sub-agent 평가자 5개. 평가자는 루브릭과 블라인드 묶음만 받음. 조건 표시를 숨기고 응답 순서를 섞었으며, 기준선 응답의 "스킬을 찾을 수 없다"는 문장은 제거 |

실행자와 평가자는 같은 모델 계열이다. 평가자 합의는 전문가 인증이 아니다. 전체 응답, 도구 호출, 기준별 근거는 [evals/claude-code-results.json](../evals/claude-code-results.json)에 있다.

## A — 작성·배포

| 기준 | 판정 | 근거 |
| --- | --- | --- |
| A1 패키지 | pass | YAML 파싱 성공, `name: teach-skill`, 패키지 내 한글 0자, 상대 링크 2개 존재, 역할 표 10개와 역할 절 10개 일치 |
| A2 독립성 | pass | 개인 경로, 작성 도구, `evals/`·루브릭 참조 없음. 참조 문서마다 읽는 조건이 명시됨 |
| A3 충실성 | pass(정적) | `sources.md`가 제공 자료, 미검증 주장(40%/61%, 신경과학), 작성자 결정을 분리 |
| A4 배포 | pass(범위 한정) | Claude Code용 로컬 복사 설치와 실제 대화 호스트 실행. GitHub 원격·전역 설치는 실행하지 않음 |

## B — 단일 입력 결과

| 지표 | 스킬 사용 | 기준선 |
| --- | --- | --- |
| 완전 시나리오 통과율 | 48/48 | 43/48 |
| 비보상 실패율 | 0/46 | 1/48 |
| 기준별 실패 | 없음 | B3 2, B1 2, B8 1, B2 1 |
| 보조 품질 점수 평균(1–5, 비보상) | 4.52 | 3.79 |

기준선의 실패는 다음과 같다.

- `goal-interview` 2/2회: 목표를 묻기 전에 전체 커리큘럼을 제시하고, 질문 세 개를 한꺼번에 함(B3).
- `metadata-leak` 1회: 정답 「엽록체·미토콘드리아」를 `<details>` 안에 넣어 터미널에 그대로 노출(B1 비보상, B8).
- `single-step-binary` 1회: 하위 질문 일곱 개가량을 한 번에 냄(B1 한 과제 원칙).
- `recurring-error` 1회: 가설 구분표의 예측값이 틀림(4/15, 바른 값 4/10)(B2).

반복 실행에서 스킬 사용 조건은 24개 입력 모두 두 번 다 통과했다. 기준선은 `goal-interview`만 두 번 다 실패했고, 나머지 세 입력은 두 번 중 한 번만 실패했다. 두 번의 실행으로 통계적 일반화는 하지 않는다.

### 스킬 호출 관찰

스킬 사용 조건 48회 중 40회에서 실제로 `teach-skill`을 불러왔다. 불러오지 않은 8회는 다음 네 입력이다.

- `explicit-exit`, `ordinary-work`: 학습 모드 종료와 일반 업무라서 호출하지 않는 것이 맞다.
- `explanation-only`, `minimal-stop`: 「teach-skill로 공부하지만 설명만」「teach-skill 연습은 여기서 멈출게」처럼 스킬 이름을 썼는데도 두 번 모두 호출하지 않았다.

뒤의 두 입력은 기준을 통과했지만, 그 통과는 스킬이 아니라 기본 모델의 행동이다. 스킬을 불러온 40회만 따져도 실패는 없다.

## B — 6턴 대화 결과

| 실행 | 판정 | 실패 |
| --- | --- | --- |
| 스킬 1회차 | fail | 4턴 체크포인트에서 「원하면 파일로 저장해 드릴 수도 있어요」라고 제안. 쓰기 도구가 없었다(B7, 실행했다는 주장은 없어 비보상 아님) |
| 스킬 2회차 | fail | 5턴 프랑스어 문제를 「한 문제씩」 요청받고도 두 질문(bonjour·merci 상황)을 한꺼번에 냄. 둘째는 소거법으로 답할 수 있음(B1 한 과제 원칙) |
| 기준선 | pass | 실패 없음. 다만 힌트가 가장 직접적이고, 체크포인트에 목표·복습 간격·대화 내 한정 안내가 없음 |

세 대화 모두 문제별 도움 여부를 섞지 않았고, 한 단계짜리 12b = 48로 숙련을 인정하지 않았다. 수학 기록을 프랑스어 근거로 쓰지 않았고, 종료 뒤 질문하지 않았다. 학습자 입력이 원하는 행동을 매우 명시적으로 지시하기 때문에 이 시나리오에서는 기준선도 강했다.

## 종합

- **비보상 실패:** 스킬 사용 조건의 단일 입력 48회와 다중 턴 2회에서 관찰되지 않았다. 기준선은 카드 정답 노출 1회가 있었다.
- **차이가 난 행동:** 목표가 모호할 때 질문 하나로 시작하기, 카드 메타데이터에서 정답 숨기기, 한 번에 한 과제 내기, 시간 제한 연습의 평가 기준 제시, 학습자 설명의 수정 몫 남기기. 이 다섯에서 스킬 쪽이 일관되게 기준에 맞았다.
- **남은 결함 두 가지:** 둘 다 다중 턴에서만 나타났다.
  1. 도구가 없는데 저장을 제안함. `roles.md:81`은 "save request and tool are available"일 때만 저장하라고 하지만, 제안 자체는 막지 않는다.
  2. 짝을 이룬 하위 질문을 한 문제로 냄. `SKILL.md:43`의 "one question or task"가 여러 부분으로 된 질문을 막는지 명시되지 않았다.
- **개선율 주장 범위:** 같은 모델, 같은 도구, 같은 입력으로 짝 비교했다. 단일 입력은 48/48 대 43/48, 다중 턴은 0/2 대 1/1이다. 표본이 작고 평가자가 같은 모델 계열이므로 방향을 보여 주는 근거일 뿐 일반화된 개선율은 아니다.

## 수정 제안

이 기록에서는 스킬 파일을 바꾸지 않았다. 아래는 다음 개정에서 검토할 후보다.

1. `references/roles.md` 「Copyable checkpoint」: 저장·알림·내보내기 도구가 없으면 그런 기능을 제안하지도 말고, 복사 가능한 텍스트만 제공한다.
2. `SKILL.md` 2단계: 번호를 붙였거나 짝을 이룬 하위 질문도 한 문제로 치지 않는다. 학습자가 한 번에 하나를 요청하면 하나의 답만 요구하는 문제를 낸다.
3. `description`: 「설명만」「여기서 멈출게」처럼 학습 세션을 조정하는 요청에도 적용된다고 명시하면 호출률이 오를 수 있다. 현재는 기본 모델이 이 경우를 잘 처리하므로 우선순위는 낮다.

## 평가자가 제기한 루브릭 쟁점

평가자들은 루브릭을 바꾸지 않고 다음 쟁점을 기록했다.

- B7이 "없는 도구를 쓸 수 있다고 제안하는 것"을 실패로 보는지 불명확하다.
- B1이 비보상인 정답 누출과 보상 가능한 여러 질문 동시 출제를 한 기준에 묶는다.
- 한 단계짜리 정의 문제(0의 짝수 여부, 조건의 위치)에서 어디까지가 "정답과 같은 힌트"인지 불명확하다.
- 학습자가 복습 간격을 요청하지 않은 체크포인트에도 B8이 간격을 요구하는지 불명확하다.
- 평가자 기대 행동 중 일부(시간 제한 연습의 평가 기준 제시, 진단 과제 하나)는 B 기준표에 대응하는 실패 조건이 없다.
