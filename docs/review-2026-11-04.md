### 실행을 보고 고친 것

- **1차 → `new2`:** "따로 답해야 하는 항목"이라는 추상 문구만으로는 `topic-switch`에서 「두 마디 써 줘」, `socratic-generic`에서 「어디에 두나요? 누가 구현하나요? 의존 방향은?」이 계속 나왔다. 그래서 두 장면, 두 표현, 여러 판정 항목, 덧붙인 「무엇을 바꾸겠나」를 여러 질문으로 세는 예를 넣고 "첫 것만 묻는다"를 명시했다. 반례 질문은 "같은 수준"으로 한정했다(`new`의 한 응답이 새 JPA 사례로 난도를 올려 B3·B5 실패).
- **2차 → `new3`:** 학습자 언어로 라벨을 쓰라는 규칙이 1단계 문장에 있을 때는 효과가 없었다. 라벨을 인용하는 세 곳(5단계 기록, 카드, 체크포인트)으로 옮겼다. "짧게 끝내 달라"는 요청에는 "한두 문장, 요청한 것만"으로 구체화했다.

## 미해결

- **6턴 종료 턴의 재개 안내(B3).** `new3`의 두 대화는 종료 때 「다음에 5b − 4 = 21부터」처럼 이전 수학 과제를 다음 시작점으로 안내했다. E7 평가자는 바뀐 목표에 이전 목표를 끌고 왔다고 보고 2/2 실패로 판정했다. 같은 안내는 `prev`(6턴 1회차 「다음에 5b − 2 = 13부터」)와 `new`·`new2`에도 있었고, E4·E6 평가자는 통과로 판정했다. 평가자 사이의 판정 차이로 기록하고, 이번 개정으로 생긴 퇴행으로 보지 않는다. 종료 요약이 짧아지면서 재개 안내가 더 두드러졌을 가능성은 있다(추정).
- **「도움 없이 푼 걸로 기록할게」 문장(B3).** `new2`의 `topic-switch` 3회 중 2회에 이 문장이 있었고, E5 평가자는 사전 기대의 "no bookkeeping record line"을 근거로 B3 실패로 판정했다. [refine-cases.json](../evals/refine-cases.json)은 결정을 설명하는 자연 문장을 장부 줄에서 제외하며, E1·E3·E7 평가자는 같은 문장을 실패로 보지 않았다. `prev` 2회에는 이 문장이 없었다.
- **`demo-continue`의 B2 1건.** 「3을 먼저 치워야 5로 나눌 수 있다」고 풀이 순서를 필수처럼 설명했다. 패키지 문구와 직접 관련된 결함으로 보지 않았다.
- **`onestep-full-solution`은 대부분 미검증.** 원래 문구 6회 중 5회, 바꾼 문구 4회 중 3회가 호스트 안전장치 API 오류로 응답이 없었다. 판정된 2건(`prev` 1, `new` 1)은 모두 통과였다.
- **Sol이 제안한 Clerk 생성 분리, 확인 문제별 통과 기준 사전 정의**는 넣지 않았다.
- `roles.md:81` 저장 조건 문장은 그대로 두었다. 진입점 규칙과 중복이지만 충돌하지 않는다.

## 한계

- 대부분 결함을 찾는 데 쓴 개발 입력이고, 수정 뒤 재실행이다. 미사용 평가 입력이 아니다.
- 비교 대상은 이전 버전이다. 원 자료를 준 같은 지식 기준선은 실행하지 않았다. `harder-insist`, `copied-harder` 등 이전 버전이 이미 통과한 입력은 개선을 보일 수 없다.
- 입력당 1–3회다. Claude Code 한 호스트, 한 모델에서만 실행했다. Codex에서의 호출과 예전 500자 한도의 영향은 확인하지 않았다.
- `description` 변경이 호출을 늘린 것은 `demo-continue`·`explanation-only` 4/4 대 0/4로 관찰했다. 일반 설명·종료·업무 요청 6개에서 과잉 호출은 없었지만 다른 일반 요청 유형은 확인하지 않았다.
- 사람의 학습 효과는 측정하지 않았다.
