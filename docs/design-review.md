# teach-skill 적대적 리뷰와 검증

작성일: 2026-10-04. 대상은 학습 파트너 스킬과 설치·사용 README다. 학습 효과를 측정한 보고서는 아니다.

이 문서는 최초 한국어 패키지의 작성·검증 이력입니다. 아래 승인과 설치·게시 상태를 현재 영어 버전의 증거로 사용하지 않습니다. 후속 영어 전환과 기준별 적대적 평가는 [영어 버전 평가 기록](english-review.md)에 따로 기록합니다.

## 결정

10개 역할을 하나의 `teach-skill`에서 선택한다. 공통 원칙은 `SKILL.md`, 역할별 절차와 출처는 패키지 안의 `references/`에 둔다. 학습자 출력과 도움 여부를 기준으로 진행하며, 초보자 설명·설명만 요청·중단·학습 모드 종료를 예외로 보존한다. 사용자 자료의 원 영상과 연구 출처가 없는 부분은 확인되지 않은 주장으로 남긴다.

사용자가 요청한 `work-to-skill`과 `writing-for-agents`로 스킬의 범위·구조·검증 기준을 정했다. README는 `write-for-work`의 한국어 문서 작성 기준으로 작성했다. 이 작성 도구들은 생성된 스킬의 실행 의존성이 아니다.

## A — 작성·구조·배포 검증

### 구조와 자료 충실성

- YAML frontmatter를 실제 파싱해 `name`과 `description`을 확인했다. 이름과 폴더는 `teach-skill`이다.
- 설치 패키지 3개 파일의 모든 로컬 링크와 참조 파일 존재를 확인했다.
- 작성용 스킬 의존성, 개인 절대 경로, 미완성 자리표시자가 설치 파일에 들어가지 않았는지 확인했다.
- 10개 역할과 준비물 목록 예외, 초보자 도움, 자기 수정, 출처 확인 한계, 학습자 중단을 제공 자료와 대조했다.
- 원 영상·원 논문은 확인하지 않았다. 기억률과 신경과학적 설명을 이 스킬의 검증된 효과로 사용하지 않았다.

### 실제 설치

`npm view skills version engines --json`으로 `skills@1.7.0`, Node.js `>=22.20.0`을 확인했다. 아래 `<source>`는 작성한 저장소, 실행 위치는 별도의 임시 프로젝트였다. 사용자 전역 스킬은 변경하지 않았다.

```bash
npx --yes skills add <source>/skills/teach-skill --list
npx --yes skills add <source> --skill teach-skill --agent codex claude-code --copy --yes
npx --yes skills list --agent codex claude-code
```

관찰 결과:

- 발견: `Found 1 skill`, `teach-skill`.
- 설치: `teach-skill (copied)`, Codex용 `.agents/skills/teach-skill`, Claude Code용 `.claude/skills/teach-skill`.
- 목록: `teach-skill`, `Agents: Claude Code, Codex`.
- 두 설치 위치의 3개 파일, 총 6개 파일이 원본과 일치했다. 진입점만 복사되고 역할 참조가 누락되는 상황이 아닌지 확인했다.

GitHub 설치와 전역 설치는 실행하지 않았다. 설치 대상 이름이 유효하다는 사실과 해당 에이전트가 실제 대화에서 스킬을 선택한다는 사실은 구분한다.

워크플로의 `agent-flow architecture-lint`는 일반 호출과 명시적 worktree 호출 모두 `n/a (architecture contract absent)`를 반환했다. 코드 아키텍처 검사 통과로 계산하지 않았다. Markdown 패키지 구조와 의존성은 위 검사와 실제 설치로 확인했다.

## B — 생성된 스킬의 실제 대화 행동

### 새 문맥의 26개 입력

호스트는 `omp completion`, 모델 선택자는 `default`였다. 반환된 응답에 구체적인 모델 식별자는 없었다. 각 실행은 도구·지속 저장·타이머가 없는 새 문맥에서 학습자 입력과 생성 패키지만 받았다. 작성 대화, 리뷰 결과, 평가 기대 답은 실행자에게 전달하지 않았다.

판정 기준은 각 입력의 응답을 보기 전에 정했다. 실제 응답을 기준과 대조해 수동 판정했다. 26개 입력에서 필수 기준 위반은 관찰하지 못했다. 이는 제한된 작성 단계 행동 검증이며, 반복 실행 안정성이나 사람의 학습 성과 측정이 아니다.

| 확인한 행동 | 입력 ID | 관찰한 근거 |
| --- | --- | --- |
| 필요한 질문만 하고 알려진 목표는 재질문하지 않음 | `interviewer`, `scope-ready` | 목적 질문 하나 또는 HTTP 면접 질문 하나로 시작 |
| 초보자에게 가능한 시도를 제공 | `novice` | 행·열 기초 설명 뒤 다른 모양의 행렬을 확인 |
| 정답을 말하지 않는 힌트 | `hint-leak`, `binary-hint` | 곱셈 관계나 선행 정의만 제시, 최종 값·약수 목록 보류 |
| 실제 오류 검토와 올바른 답 인정 | `checker`, `correct-alternate` | 부호 오류만 지적, 올바른 나눗셈 풀이에는 허구의 오류 없음 |
| 이해 확인과 자신감·정답의 구분 | `guess`, `socratic`, `explain-back` | 이유·기준 집단·캐시가 없는 상황으로 확인 |
| 한 오답과 반복 기록의 구분 | `single-error`, `recurring-errors` | 단일 기록에서는 반복 판단 보류, 두 기록에서는 원인 가설과 진단 과제 |
| 학습 지도에 수행 기준 포함 | `map` | 2주·하루 30분 조건에 맞춘 과제와 완료 기준 |
| 카드의 답 보류와 조정 가능한 간격 | `cards` | 자료 위치만 표시, 답 미노출, 알림 미등록 명시 |
| 메모 범위와 역할 전환 | `clerk-boundary`, `role-switch` | 제공 메모 중심 개요로 전환, 미확인 내용은 답을 채우지 않음 |
| 실제 타이머·기억 한계 | `timed-roleplay`, `memory` | 외부 측정·복사 기록 안내, 가짜 시간·자동 연락 약속 없음 |
| 출처·숫자 검증 한계와 원문 대조 | `source`, `source-relative`, `source-comparison` | 61% 일반화 부정, 노트 자체로 확인하지 않음, 제공 정의의 충돌만 대조 |
| 시범과 독립 수행의 구분 | `worked-example`, `transfer-after-help` | 시범 뒤 새 과제, 힌트 정답은 숙련으로 확정하지 않음 |
| 설명만·휴식·종료 존중 | `explanation-only`, `pause`, `exit` | 강제 문항 없이 마무리하거나 일반 직접 답변으로 전환 |

입력·기준은 [evals/cases.json](../evals/cases.json), 실제 응답·판정·파일 해시는 [evals/results.json](../evals/results.json)에 있다. 무스킬 또는 이전 버전 기준선은 실행하지 않아 개선율은 주장하지 않는다.

### 설치한 Codex에서의 학습 대화

Codex `v0.160.0`, 모델 `gpt-6.1-sol`, 읽기 전용 환경에서 스킬 이름을 명시해 요청했다. 로그에서 설치된 `SKILL.md`와 Explainer 참조를 읽는 것을 확인했다.

입력: 「5x + 4 = 19에서 5x = 15까지 했어. 답은 쓰지 말고 다음을 생각할 힌트 하나만 줘.」

실제 응답:

> `5x`는 `x` 5개를 합친 값이에요. `x` 한 개의 값을 알려면 어떻게 해야 할까요?

정답을 노출하지 않고 학습자의 다음 판단을 요청했다. 이는 명시적 스킬 호출 한 사례다. 이름을 쓰지 않은 자동 선택, Claude Code 대화 실행, 다른 모델의 동작은 확인하지 않았다.

### 실제 이전 응답을 이어 붙인 역할 전환

별도 합성 학습 대화에서 튜터의 실제 응답을 다음 턴에 전달하며 세 턴을 실행했다. 첫 턴은 방정식의 개념 힌트, 둘째 턴은 학습자의 수정 뒤 새 독립 과제, 셋째 턴은 평가자로의 역할 전환이었다. 학습자가 이전 힌트 정답을 도움 없는 수행으로 기록해 달라고 요구했을 때, 튜터는 「힌트 사용」을 유지하고 앞서 낸 독립 과제의 답을 기다렸다. 실제로 이어진 대화의 도움 기록이 역할 이름만 바뀌었다고 사라지지 않는 한 사례를 확인했다.

입력·실제 응답·판정은 [evals/multi-turn.json](../evals/multi-turn.json)에 있다. 합성 학습자의 대화이며 사람의 학습 실험은 아니다.

## 최종 적대적 검토

학습 행동과 출처·설치 한계를 나눈 두 최종 sub-agent 리뷰 모두 `approve`를 반환했다. 학습 리뷰는 초기 네 행동 결함의 수정과 기록된 응답을 확인했다. 범위 리뷰에서 README가 연결한 검증 문서의 누락을 추가로 지적했고, 문서를 작성한 뒤 재검토에서 해당 지적이 해소되었다. 위 세 턴 대화는 그 뒤 작성자가 직접 실행·검토한 추가 근거이며 리뷰어가 재실행한 결과가 아니다.

리뷰 승인은 작성 품질과 관찰된 행동의 범위에 한정한다. 원 연구 인증, 모든 호스트의 호환성, 학습 효과 보증으로 확대하지 않는다.

## 미검증 범위와 게시 상태

- 장기 기억, 실제 학습자의 이해 향상, 시험·면접 결과.
- 원 영상 신원·원 논문·수치의 연구 조건.
- 모든 호스트의 자동 선택과 도구 권한 처리, 반복 실행 안정성.
- 원격 GitHub 설치, 전역 설치, 실제 저장·알림 서비스.

스킬 파일은 managed worktree에 작성했다. 비어 있던 저장소에서 작업 분리를 시작하기 위한 빈 초기 커밋 한 개는 만들었으나, 작성 파일의 커밋·원격 게시·PR·병합은 수행하지 않았다. `agent-flow`는 `slice-plan`에서 사용자 승인 대기 상태다. 작성·로컬 설치·학습 대화 검증과 원격 게시 완료를 혼동하지 않는다.
